# MuMu + ADB 导出欢太健康数据：实施流程

## 目标和边界

目标是把欢太健康中“屏幕上能查看到”的历史数据保存为：

1. 原始证据：每日/每页截图与 UI XML；
2. 结构化记录：JSONL/CSV，支持中断后续跑；
3. 可追溯关系：每条记录都能定位到对应的截图和采集时间。

优先读取 Android UI 控件中的文字；只有控件树不提供文字时才启用 OCR。折线图、柱状图等图形不能仅靠 OCR 无损恢复为原始采样点，因此先保存原图，并把“图表数字化”列为独立的后处理阶段。

## 当前已确认的环境

- MuMu 12 的 ADB：`C:\Program Files\Netease\MuMu\nx_device\12.0\shell\adb.exe`
- 连接地址：`127.0.0.1:7555`
- 欢太健康包名：`com.heytap.health`
- Android 版本：12
- 当前基准显示：`1440x2560`、密度 `640`
- 首页和心率详情页的文字、资源 ID、日期前后按钮均可从 UI 树读取

不要在正式采集中途修改模拟器分辨率、显示缩放、字体大小、APP 语言或深浅色模式。

## 流程总览

### 0. 每次开工前：环境体检

```powershell
python .\ohealth_exporter.py doctor
```

验收：ADB、欢太健康、UI 可读均为 `[OK]`。若“前台应用”不是欢太健康，把 APP 切回前台即可。

### 1. 建立页面样本库

对首页以及步数/活动、心率、睡眠、血氧、运动记录等详情页分别执行：

```powershell
python .\ohealth_exporter.py capture
```

每个样本包含 `screen.png`、`window.xml`、`labels.json`。先用样本确认哪些数据可从 UI 树直接读取，哪些只能截图/OCR。

### 2. 单日单指标探针

先从心率开始，因为已确认详情页具有：

- `tv_date`：当前日期；
- `iv_pre` / `iv_next`：前一天/后一天；
- `tv_heart_rate_range`：全天范围；
- `tv_title` + `tv_status`：静息、步行平均、睡眠基准等摘要。

人工进入“心率 → 日”页后执行：

```powershell
python .\ohealth_exporter.py probe-heart
```

验收：生成 `output\heart_rate\<时间>\record.json`，且日期和页面显示一致。

### 3. 每日遍历器（下一实现阶段）

为每个指标实现相同状态机：

1. 识别当前指标和“日”视图；
2. 读取日期并保存 UI XML + 截图；
3. 提取摘要字段；
4. 先原子写入单日 JSON，再更新 checkpoint；
5. 点击 `iv_pre`；
6. 等待日期变化和页面稳定；
7. 到达起始日期、连续空白阈值或人工停止时结束。

遍历器必须支持 `--start-date`、`--end-date`、`--resume`、最大天数和每步超时，禁止没有边界的死循环。

### 4. 指标实施顺序

建议顺序：

1. 心率：控件最清楚，用于验证遍历和断点机制；
2. 睡眠：总时长、评分、阶段摘要，原图保留睡眠分期图；
3. 步数/活动：步数、消耗、活动时长、站立等；
4. 血氧：范围/平均值/睡眠血氧摘要；
5. 运动记录：每条记录单独进入详情，按记录 ID 去重；
6. 体重、压力和其他卡片：按实际需要补充。

### 5. OCR 兜底

只有在 UI XML 中缺失字段时才处理截图：固定裁剪区域 → 图像预处理 → PaddleOCR → 正则清洗 → 与日期/指标绑定。OCR 结果必须附带置信度并保留原图，不直接覆盖 UI 控件提取到的值。

### 6. 汇总与质检

最终至少生成：

- `records.jsonl`：完整、适合恢复和再处理；
- 各指标 CSV：便于 Excel/数据分析；
- `manifest.json`：APP 版本、分辨率、导出范围、成功/空白/失败天数；
- `failures.jsonl`：失败日期、页面状态、错误与证据路径。

抽检首日、末日、每月随机一天，并核对跨年、闰日、夏令时无关但日期切换、无数据日和弹窗干扰。

## 现在需要的人工操作

1. 保持 MuMu 开着，暂时不要改分辨率；
2. 确认欢太健康已同步到最早可见历史；
3. 按指标进入详情页时保持“日”视图；
4. 若出现隐私授权、升级说明或功能引导，先人工处理一次；
5. 先用少量日期试跑，核对准确后再挂机全量导出。

## 隐私与备份

`output\` 和 `.diagnostics\` 含个人健康信息，默认不进 Git。正式全量运行前，把输出目录放到有足够空间的位置；完成后至少保留两份加密备份。不要把截图、XML 或 CSV 上传到公开 issue/仓库。
